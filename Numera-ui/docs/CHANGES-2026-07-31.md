## The changes

### BACKEND — `cad2484` — fix the session-killing 409  ← the big one

`next_question_updates()` serves the next question from the Qdrant bank but
left the old Student Model event in place, so every schema lookup afterwards
409'd ("Student Model did not return metadata for ALG_1STEP_GP_F01/F02") and
the session was dead with no recovery.

The fix is one key in the advance dict: `student_model_event: None`. Every
schema reader already handles the None case by degrading to the plain
bank-question flow — the flow that worked before Schema 3.0 — and the next
phase start stores a fresh, consistent event. Also rewrites the 409 message,
which blamed the Student Model for an id the Tutor Backend assigned itself and
misdirected two debugging efforts.

Regression test included. Full backend suite: **313 passed**; the 6 failures
also fail on untouched `main` (env-dependent, verified by stashing).

**To revert:** `git revert cad2484` — restores previous behaviour exactly.

### BACKEND — `8952e2c` — voice tutor calls get 40s, same as canvas

`/voice/transcript` inherited a 15s client-default timeout while
`/canvas/submit` explicitly gets 40s for comparable LLM work. Slowest measured
voice turn is 12.5s (n=121) — no timeout has fired yet, but the margin was 17%.
One line, plus the test updated to pin the new budget.

**To revert:** `git revert 8952e2c` — but then also revert frontend `df57b73`
(below), which follows this timeout.

### BACKEND — `2419a2a` — Deepgram KeepAlive

Deepgram kills a stream that gets no audio for ~10s, and the frontend sends
nothing while the student is muted — 8 kills in two days of logs, each costing
the student an utterance mid-conversation. Per Deepgram's docs, a `KeepAlive`
frame every 5s. One task per connection, cancelled in the existing cleanup.

**To revert:** `git revert 2419a2a`.

### FRONTEND — `df57b73` — watchdog follows the new timeout; `actions` typed

- The stuck-turn rescue window moves 20s → 45s because it is derived from the
  backend timeout that moved 15s → 40s. A test enforces the coupling.
  **Paired with backend `8952e2c`** — revert both or neither.
- `VisualCue` gains the optional `actions` field the backend has been sending
  since PR #55. Fixes the type error that came in with yesterday's pull.

### FRONTEND — redeployed

The deployed bundle was built **before** Sanya's 30 July frontend changes
landed, so the live app was ignoring the scaffold and visual-cue fields the
backend now sends over the WebSocket. Rebuilt from current `main` (117 tests,
tsc clean) and redeployed. If support cues seemed to "do nothing" yesterday
afternoon, this stale bundle is why.
