## 2. Static export — the decision, and a correction

### The correction

From your §1 Cause 2:

> "The reported bug is fixed regardless, because the transition itself is a
> client-side `router.push` — Next routes it in the browser with the bundle
> already loaded and never requests that document."

The last clause does not hold for Next 15 App Router, and since it is what
downgrades this item to "refresh and deep-links only", the framing has to change.

**The client router does request a per-route document.** Loading
`/app/orientation/ALG-ORI-02/` on the deployed app with the network panel
recording, the app's own client-side redirect to login fired:

```
GET https://nablix.ai/app/login/index.txt?_rsc=ZmCQ44b92m4mXe_R → 200 OK
```

That is the router fetching the flight payload for the route it is navigating
to, client-side, in our exact static-export build. A `router.push` to a new
topic issues the same request.

**And for a backend code that request is answered wrongly, with a success status:**

```
/app/login/index.txt?_rsc=…                    → 200   5487b  text/plain  1:"$Sreact.fragment"…
/app/orientation/algebra/index.txt?_rsc=…      → 200   6674b  text/plain  1:"$Sreact.fragment"…
/app/orientation/ALG-ORI-02/index.txt?_rsc=…   → 200  10990b  text/html   <!DOCTYPE html>…
/app/diagnostic/ALG-ORI-02/index.txt?_rsc=…    → 200  10990b  text/html   <!DOCTYPE html>…
```

`try_files … /app/index.html` launders the miss into a 200 carrying HTML. The
router gets an unparseable body and no error status to detect it by. The root
site 404s correctly on the same shape, so it is that fallback rule and nothing
else.

**Which means the target screen cannot render.** There is no flight payload for
`ALG-ORI-02` anywhere on disk, and App Router cannot build a route segment
without one, however much of the bundle is already loaded. A hard load confirms
what the server hands back: it pulls `app/page-*.js`, the **root** route — the
guided lesson, not orientation.

So this is not a deep-link concern. It is on the transition path, and my best
reading — flagged as inference, because it is one — is that a student lands on
the guided lesson for the new topic instead of its orientation or diagnostic.
That is the 28 July failure shape again.

**What is still unproven, on both our sides:** the router's exact recovery
behaviour on a 200-with-HTML payload. Establishing it needs an authenticated
session driving a real handoff, which is item 5.

None of this changes that your three fixes are correct. It changes what we can
say is finished: the blank page is gone, the transition is not yet verified.

### The decision

**Query param — `/orientation?topic=ALG-ORI-02`.** One static file, one flight
payload, correct for any code the curriculum ever gains. It closes the
deep-link failure and the client-navigation failure in the same move.

The sentinel catch-all still depends on nginx answering RSC requests correctly,
and the evidence above is that this is exactly the part that is silently wrong
today — so it fixes the visible half and leaves the mechanism that caused it.

Yes, it changes every topic URL. Take that cost.

**Separately, and regardless: make nginx 404 a missing `*/index.txt`** instead
of returning the shell under a 200. A router that can see the miss degrades far
better than one that cannot, and this is the difference between the next failure
of this kind being visible or silent.
